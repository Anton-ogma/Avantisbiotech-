# Приложение В. Формат CSV и маппинг DICAM

Источник: `server/routes.ts:5730-5766` (DIERS), `5846-5885` (Myoline).

---

## В.1 Откуда берётся файл

DIERS DICAM Software → **File > Export > CSV**. Полученный файл пациент
загружает через кнопку «Импорт CSV». Прямого подключения к прибору или к БД
DICAM в системе нет и не предполагается (см. ФТ-5 основного ТЗ).

---

## В.2 Правила разбора (DIERS)

| Шаг | Правило | Код |
|---|---|---|
| 1 | Файл читается как UTF-8 целиком в память | `fs.readFileSync(path, 'utf8')` |
| 2 | Разбивка на строки `\r\n` или `\n`, пустые строки отбрасываются | `split(/\r?\n/).filter(...)` |
| 3 | Меньше 2 непустых строк → **400** `Empty CSV` | |
| 4 | Первая строка — заголовки | |
| 5 | Разделитель — любой из `;` `,` `\t` | `split(/[;,\t]/)` |
| 6 | Двойные кавычки удаляются из заголовков и значений | `.replace(/"/g,'')` |
| 7 | Каждая последующая строка → **отдельное исследование** | цикл `for i=1..n` |
| 8 | Недостающие значения в строке → `''` | `vals[j] \|\| ''` |

**Ограничения разбора.** Разделитель применяется посимвольно, без учёта
кавычек и экранирования: значение вида `"Иванов, И.И."` будет разорвано по
запятой. Смешанные разделители в одном файле не различаются. Кодировки, кроме
UTF-8 (в частности Windows-1251, типичная для русской локали DICAM),
не поддерживаются. Размер файла и число строк не ограничены.

## В.3 Определение даты и названия

```
study_date ← Date | Datum | date | study_date | <текущая дата>
title      ← Title | Titel | "Исследование {N}"
```

Поиск — по точному имени столбца, в указанном порядке. Формат даты не
валидируется: что было в ячейке, то и попадёт в `study_date`. Немецкие
заголовки (`Datum`, `Titel`) поддержаны, потому что DICAM — немецкий софт.

## В.4 Раскладка столбцов по группам

Для каждого заголовка проверяется **вхождение подстроки** ключа
(`header.includes(key)`), а не точное совпадение. Порядок проверки:
`spine` → `posture` → `gait`; **первое совпадение выигрывает**, дальше
заголовок не рассматривается.

### SPINE_KEYS (16)

```
VP, VP_SD, TP, TP_SD, LP, LP_SD, KA, KA_SD, LA, LA_SD,
Kyphosis, Lordosis, Scoliosis, Trunk_Imbalance, Pelvis_Tilt, Sacrum_Inclination
```

### POSTURE_KEYS (7)

```
Trunk_Flex, Lat_Dev, Rot_Asym, Shoulder_Tilt, Hip_Tilt, COG_X, COG_Y
```

### GAIT_KEYS (6)

```
Step_Length, Stride_Width, Cadence, Speed, Stance_Phase, Swing_Phase
```

**Ключ сохраняется под исходным именем заголовка**, а не под именем ключа.
Столбец `Kyphosis_Angle_deg` попадёт в `spine_params` под ключом
`"Kyphosis_Angle_deg"` — сравнение таких исследований с ручным вводом
(`"Kyphosis"`) не сойдётся по ключу: параметры окажутся разными строками таблицы.

### Ловушки подстрочного матчинга

| Заголовок | Куда попадёт | Почему |
|---|---|---|
| `VP_Max` | spine, ключ `VP_Max` | содержит `VP` |
| `Gait_Speed` | posture? нет → gait | `Speed` — gait-ключ |
| `Trunk_Flexion_Max` | posture | содержит `Trunk_Flex` |
| `Trunk_Imbalance_Lat_Dev` | **spine** | spine проверяется первым |
| `LP_Rotation` | spine | содержит `LP` |
| `Speed_Cadence_Ratio` | gait | содержит и `Speed`, и `Cadence` |

Двух- и трёхбуквенные ключи (`VP`, `TP`, `LP`, `KA`, `LA`) особенно склонны
к ложным срабатываниям на любом заголовке, где эти буквы встречаются подряд.

## В.5 Фолбэк, ломающий данные

```js
JSON.stringify(Object.keys(spine_params).length ? spine_params : row)
```

Если **ни один** заголовок не распознан как спинальный, в `spine_params`
записывается **вся строка CSV целиком** — все столбцы файла, включая ФИО,
идентификаторы, служебные поля. Такое исследование:

- покажет в карточке «Позвоночник» произвольный набор столбцов файла;
- в сравнении даст десятки мусорных строк;
- продублирует содержимое `raw_data`.

`posture_params` и `gait_params` в этом случае остаются пустыми. Зарегистрировано
как **Д-09**, приоритет P1.

---

## В.6 Что сохраняется

```
spine_params   ← распознанные spine-столбцы (или весь ряд — см. В.5)
posture_params ← распознанные posture-столбцы
gait_params    ← распознанные gait-столбцы
raw_data       ← весь ряд как объект {заголовок: значение}
source         ← "csv_import"
device_type    ← из поля формы, default "formetric4d"
notes          ← ""
```

Дедупликации нет: повторная загрузка того же файла создаст полный дубль
всех исследований.

## В.7 Пример входного файла (DIERS)

```csv
Date;Title;Kyphosis;Lordosis;Scoliosis;Trunk_Imbalance;Pelvis_Tilt;COG_X;COG_Y;Cadence
2026-01-10;Исходное;45.1;40.2;1.4;7.8;2.4;0.9;14.1;108
2026-03-14;После курса;42.3;38.7;2.1;5.2;1.8;0.3;12.4;112
```

Результат — два исследования:

```jsonc
{
  "study_date": "2026-03-14",
  "title": "После курса",
  "spine_params":   { "Kyphosis": "42.3", "Lordosis": "38.7", "Scoliosis": "2.1",
                      "Trunk_Imbalance": "5.2", "Pelvis_Tilt": "1.8" },
  "posture_params": { "COG_X": "0.3", "COG_Y": "12.4" },
  "gait_params":    { "Cadence": "112" },
  "raw_data":       { "Date": "…", "Title": "…", /* все столбцы */ },
  "source": "csv_import"
}
```

## В.8 Маппинг Myoline

Отдельный обработчик (`/api/myoline/import-csv`) с той же механикой разбора,
но со словарём мышц:

| Ключ в заголовке | Канал |
|---|---|
| `ES_L` / `ES_R` | Erector Spinae L / R |
| `QL_L` / `QL_R` | Quadratus Lumborum L / R |
| `GM_L` / `GM_R` | Gluteus Maximus L / R |
| `RF_L` / `RF_R` | Rectus Femoris L / R |
| `TA_L` / `TA_R` | Tibialis Ant L / R |
| `GS_L` / `GS_R` | Gastrocnemius L / R |

Матчинг тоже подстрочный (`h.includes(k)`). Каждому распознанному столбцу
соответствует канал `{ name, raw_value, unit: "µV" }`; единица измерения
проставляется жёстко как микровольты, независимо от содержимого файла.
Название исследования формируется как `ЭМГ {дата}`, `analysis_results` — `{}`.
Столбца `Title` обработчик Myoline не читает.

Пример:

```csv
Date;ES_L;ES_R;QL_L;QL_R;GM_L;GM_R
2026-03-14;41.0;38.6;22.4;19.8;30.1;33.7
```

## В.9 Требования к целевой версии импорта

1. Разбор CSV библиотекой с поддержкой кавычек и экранирования вместо `split`.
2. Автоопределение кодировки либо явный выбор (UTF-8 / Windows-1251).
3. Лимиты: максимальный размер файла, максимальное число строк, проверка MIME.
4. Точное сопоставление ключей (словарь `заголовок DICAM → канонический код`)
   вместо `includes`, с нормализацией имён к каноническому виду.
5. Убрать фолбэк «весь ряд в `spine_params`»; вместо него — вернуть отчёт
   о нераспознанных столбцах.
6. Предпросмотр перед импортом: сколько строк, какие столбцы распознаны,
   какие проигнорированы.
7. Батч-вставка одним запросом вместо `INSERT` на строку.
8. Дедупликация по `(user_id, study_date, device_type)` или по хешу `raw_data`.
9. Удаление временного файла в `finally`, а не только на успешном пути.
